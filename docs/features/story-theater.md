# 见面 · 剧情剧场与虚构剧情树

## 目标与边界

剧情树只属于 `writesToCharacterMemory === false` 的虚构剧场。真实时间陪伴继续使用原线性会话、角色镜像与正常记忆归档，不做树迁移，也不改变原来的编辑、重写、删除和上下文行为。

本功能解决“同一段虚构剧情可以从任意历史楼层显式岔开，并长期保留多条可能性”的需求。分支不是自动生成按钮：`从这里新建分支` 只创建一条空路线；用户回到剧情页后第一次推进，才会在该分支写入新楼层并调用 AI。

## 基础剧场的创作定位与上下文边界

剧情剧场不仅用于“把一段设定续写成小说”，也可以作为作者的**角色心理沙盘 / 时间线试演工具**：作者先给出当前阶段已经成立的条件，让多个角色按各自人格、认知与心理反应继续演绎，再用跑出来的细节检查原大纲是否合理。这里的大纲不是必须忠实执行的最终真相；试演中发现人物动机、心理承接或因果不成立时，允许作者反过来修改外部大纲。

当前实现有几个必须明确的上下文边界：

- 虚构剧场关闭「记忆输入」时，角色仍会读取名字、核心指令和世界观；`buildBareTheaterActorContext()` 会把 `systemPrompt` 与 `worldview` 每轮送入剧情请求。它们适合放长期稳定的人格、世界规则和角色边界，不适合作为“只有作者知道、人物尚未走到”的完整未来大纲。
- `StoryTheaterEntry.premise` 不是一次性开场备注。会话生成时会把标题与 `premise` 组成「当前剧情」并在每轮持续注入，因此也不应把整部未来时间线放进去。它更适合记录当前场景已经成立、需要长期守住的前提。
- 完整成文大纲由作者在 SullyOS 外部文档管理即可。当前没有新增“作者大纲区”，也不把未来事件逐段自动释放给模型；什么时候补充剧情方向，由作者在实际推进时主动决定。
- 角色之间的知识差暂不做结构化知情表。作者可以继续用自然语言说明，例如“但 A 不知道的是……”，让本轮指令直接约束当前场景。
- 当前历史 prompt 会把用户楼层统一标成“当前身份给出的推进（用户侧）”，没有独立的导演消息类型；但内置夜班放映室预设已经明确规定，非剧情指令、设定修改、括号内操作说明和 OOC 不进入文学转述，只执行实际指令。实玩已经能够在用户角色离场后用自然语言继续指挥其它角色的互动，因此现阶段**不要求额外增加「角色 / 导演」输入切换、导演日志或单独记录卡**。
- 作者可以在角色身份中直接参与场景，也可以在需要时从故事外推动镜头、其他角色互动、时间或事实；重点是让 AI 提供多个角色的心理与即时反应，帮助作者验证人物是否真的会走向原先设想的剧情，而不是把用户角色固定成所有事件的中心。

这组边界意味着：**世界观负责稳定事实，剧情前提负责当前阶段，未来方向保留在作者手里；试演结果反过来可以修改作者原本的方向。**

## 2026-10-03 · 实玩中的推进控制观察

本轮实玩暴露出的主要问题不是单纯“输出太长”，而是**模型有时在一个回复中连续取得过多剧情决定权**：当前场景前半段合理，但后半段可能替角色做出阶段性动作、主动引入下一件关键事件，或过早收束当前场景。用户重掷后可能不再出现同一问题，说明至少一部分属于采样分支，而不是稳定可复现的确定性 Bug。

一个现场例子是：角色长期以面罩示人，第一次吃饭中即使已经聊得投机、出现精神契合和一定交心，也不代表“摘下面罩”这个关系阶段节点已经成熟；某次生成却直接越过了这一门槛，而重掷后没有发生。这里真正敏感的并非动作大小，而是**动作是否跨越长期防御、秘密、身份暴露或关系阶段**。

当前代码与内置预设本身会放大“继续往前走”的倾向，这一点要与“篇幅短”区分：

- 夜班放映室 V6.27 当前采样参数为 `temperature: 1.1`、`topP: 0.88`，保留较高的生成分支自由度。
- 「短」篇幅实际仍要求正文通常 700—1100 字，并且至少完成“承接—施力—转向”三拍；字数不足时还明确要求增加新话头、新动作或新后果。
- 常驻「长片意识」要求每轮“成事”、产生变化并留下可以继续接演的新局面；转述规则还要求越过用户输入终点。也就是说，当前的“短 / 中 / 长”主要控制文字量，不等价于“剧情决定权少 / 更早把控制权交还给用户”。

因此如果以后再次优化这个问题，首先应把**文字长度**与**剧情推进 / 交棒频率**视为两个维度，而不能只继续缩短字数。更值得观察的是：模型能否在当前关系阶段内自由写心理、语言、小动作和可逆反应，同时对摘下面罩、核心秘密揭露、关系确认、不可逆承诺等“跨阶段动作”保持克制。

这目前只是经过实玩确认的产品观察，**不是已确定的改造任务**。当前选择是先继续使用现有虚构剧场、必要时重掷或用自然语言纠偏，等同类问题反复出现后再决定是否需要新的推进控制机制。

## 数据合同

- 正文仍复用 `messages` 表，中央线程仍是 `story-theater:${entryId}`，不新增 IndexedDB store，也不升级 DB 版本。
- 每条虚构剧情消息在 `metadata.storyParentMessageId` 保存父楼层，在 `metadata.storyBranchId` 保存所属分支。拓扑不能再从全局自增 Message ID 猜测。
- `StoryTheaterEntry.timeline` 保存根分支、当前分支、当前游标和分支目录；分支名属于分支/边，不属于共享祖先节点。
- 每个 Message 是一个节点。共享祖先只存一份；不同分支通过 parent 指针复用祖先，不复制正文。
- `StoryTheaterArchive.messageIds` 保存精确、有序的归档楼层集合。`fromMessageId/toMessageId` 仅保留旧数据兼容与展示，不能用于树上的适用性判断。
- 新向量归档使用 `story-theater:${entryId}:archive:${archiveId}` 独立分区，MemoryNode 同时保存 `storyTimelineScope`。兄弟路线不会共用同一个新向量分区。

## 旧数据迁移

`ensureStoryTimeline()` 在旧虚构剧情首次打开时，用一次 `messages + story_theaters` 读写事务完成懒迁移：

1. 按旧线性顺序把全部楼层挂到单一根分支，保留原 ID、role、content 和 timestamp。
2. 当前游标指向旧线性末端。
3. 旧归档按当时线性范围补齐精确 `messageIds`。
4. 条目与楼层同事务提交；重复执行不再改写。

真实陪伴会在入口直接跳过。旧向量归档继续读取原 `story-theater:${entryId}` 分区；只有迁移后的新归档采用每批独立分区，避免伪造无法从旧节点可靠恢复的来源映射。

## 当前路径与生成规则

- 正常剧情页、导出、世界书扫描、预设 history、上一轮关系值、事件盒和独立向量召回都只读取“根 → 当前游标”的祖先链。
- 兄弟分支正文不会进入 prompt。事件盒只有在其 `messageIds` 完整、连续且顺序一致地出现在当前路径时才适用。
- 当前游标有后续时禁止隐式续写；必须显式创建分支。空分支虽然停在有后续的岔路点，但因 active branch 尚无自己的楼层，允许写入第一条新消息。
- 普通编辑、单层删除和重写只允许当前叶节点。带后续的历史节点必须走剧情树里的新建分支或删除子树。
- 重写只允许当前游标上的 assistant 叶节点；不能改写兄弟路线或已归档节点。

## 导出格式

剧情页的导出按钮会先选择格式，导出范围合同不变：虚构剧情只导出“根 → 当前游标”的当前路线，真实陪伴导出完整线性会话。

- **Obsidian 卡片版（`.md`，推荐）**：移除 XML 标签，把场景、幕后暗格、镜头债、关系变化、世界线提示与小剧场转换为标准 Markdown 标题、正文和 Obsidian callout。
- **纯正文阅读版（`.txt`）**：只保留用户推进内容与 `<story_text>` 小说正文，不带幕后面板、关系数据或协议标签。
- **系统原始协议版（`.txt`）**：保留既有逐条原始内容和 XML，用于排错或回灌。

格式化只发生在下载时，统一复用现有剧情块解析器，不改写 IndexedDB 中的消息、时间线或归档。

## 图谱与操作

`StoryTimelineGraph` 使用项目已有 `@xyflow/react + @dagrejs/dagre`，稳定自上而下布局。深色全屏图谱以紫色标记当前路径、灰色弱化历史路线，包含 Minimap、Controls、只看当前路线、回到当前节点和右侧/移动端底部详情面板。

- 点击节点只选择并查看，不自动切换。
- 详情面板显示原文、角色、时间、分支、同级数与路径面包屑；切换和新建分支是独立按钮。
- 空分支使用虚线占位节点。
- 非当前路线中连续、无分叉且至少 5 条的长链压成“折叠 N 条消息”，点击后临时展开。
- 分支可重命名。删除子树会删所选节点及后代；删除分支会删该分支和子分支，但保留共同祖先。

## 删除、归档与备份

子树/分支删除通过 `messages + story_theaters` 单事务更新正文、分支表、当前游标和归档目录。凡精确 `messageIds` 与删除集合相交的归档都失效；对应新式向量分区的节点、向量和关联边随后清理。共同祖先和其它分支不在删除集合中。

完整备份原本已同时包含 `storyTheaters` 与 `messages`；timeline、branches、archives 和消息 metadata 都是既有对象上的字段，因此随现有普通完整备份及 v2 全量/纯文字备份自然往返，不新增旁路文件。

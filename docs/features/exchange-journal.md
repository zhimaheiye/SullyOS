# 交换日记

新日记的默认模板可以配置。入口是日记选择页的「默认模板」，以及日历页的「设置新日记的默认模板」。弹窗标题是「新日记的默认模板」。

## 档案信息

- 类型：项目既有桌面 App 的持续改进
- 当前状态：角色交换流程保留；用户同日正文与可选自我观察跨日记本同步、空白页模板与未回复日记跨日清理已实现
- 持久化：IndexedDB `diaries` store，按 `charId` 建索引

## 核心产品语义

交换日记的每条 `DiaryEntry` 仍属于一个角色与一个日期，包含用户页 `userPage` 和可选的角色页 `charPage`。用户在某本日记里写下正文并不等于已经向该角色索取回信：

- “保存”只做本地持久化，不请求模型，不生成角色回复，也不写入长期记忆。
- 只有用户进入具体角色的日记本并主动点击“查看 TA 的今日”时，才为该角色加载上下文、调用主 API 并生成 `charPage`。
- 成功取得角色回复时，双页日记会生成或更新该角色主聊天中的快照卡；普通保存不更新卡片，单方面写下的用户页不进入聊天上下文。

## 2026-08-15 · 同日用户正文跨角色复用

### 需求

用户每天只需在任意一本角色日记中写一次正文与可选观察。点击保存后，其余尚未交换的角色日记获得同一份仍可编辑的用户内容快照，效果等同于用户逐本粘贴并保存，但不等同于逐本点击获取角色日记。

### 实现边界

- 同步字段为 `userPage.text` 与可选 `userPage.observations`；观察按来源快照替换而不是逐字段合并，因此来源删除模块或事件后，未交换目标也会删除对应旧内容。
- 目标记录已存在且没有 `charPage` 时，只替换正文与观察，保留纸张、贴纸、归档状态、时间戳与聊天消息 ID。
- 目标记录不存在时，创建只有用户页的本地记录；不创建 `charPage`，不创建聊天卡，不调用 AI，不写记忆。
- 目标记录已有 `charPage` 时视为已经交换，后台广播整条跳过，不改用户页、角色页或聊天卡；这不限制用户打开该日记后主动编辑、重写或删除。
- 每个目标角色独立保存。个别日记同步失败时，当前日记仍保存成功，并在界面列出未同步成功的角色。

## 新日记的默认模板

三种模式存在本机 `journal_default_template_v1`，并随整档备份的 `journalDefaultTemplate` 进出。没有这个字段的旧备份不会清掉本机已保存的选择。

- **使用内置反思模板**：预填不足之处、三件好事、明天最重要的一件事、今天学到的一点、祝福、感谢和大脑清仓。正文就是 `utils/journal.ts` 的 `DEFAULT_USER_DIARY_TEMPLATE`。
- **使用我写的模板**：预填用户保存的自定义正文。切回内置模式时，这段自定义草稿仍留在设置里，只是新页面暂时不用它。
- **从空白页开始**：新页面是真正的空字符串。零点也不会自动存出一篇有内容的日记。
- **恢复内置模板**：把模式设回内置，并保留已写下的自定义草稿。

模板只在正文 `trim()` 后为空时填入。已经保存的日记、正在看的历史页，以及只打开还没保存的页面，都不会被改写。打开页面本身不落库，仍要点「保存」才会写入并同步。

保存后的提示是「默认模板已保存，只用于之后新打开的空白页」。

## 零点打开新的一天

- 交换日记按设备本地自然日切换。应用停留在当天书写页跨过零点时，先沿用普通“保存”流程保存并同步刚结束当天的正文，再打开新日期。
- 新日期是独立的 `DiaryEntry`，用户页使用当时生效的默认模板。旧条目的保留规则见下方“未回复日记跨日清理”。
- 只有正在编辑“刚结束的那一天”才自动切换。零点查看更早的历史日记时，不会被强制跳回今天。
- 原封不动、从未编辑的模板页不会在零点被保存成一篇历史日记。正文、纸张或贴纸有改动时才先保存。
- 应用关闭期间无需后台计时。重新打开后，“写今天的日记”使用当日日期和当前模板。

## 2026-08-23 · 未回复日记跨日清理

- 日记所属本地自然日结束后，仍没有 `charPage` 的记录会被自动删除；当天记录不会提前删除。
- 已经主动点击“查看 TA 的今日”并取得角色回复的记录永久保留，不受跨日清理影响。
- 应用停留在交换日记中跨过零点时立即清理；应用关闭期间无需后台运行，下次打开交换日记时会补清所有已过期的未回复记录。
- 正停留在刚结束日期的书写页时，先按普通保存流程保存并广播，再执行清理。于是有回复的角色本保留完整双页日记，其余仍未回复的角色副本随跨日清理删除。
- 再次点击“保存”只向尚未交换的目标同步最新用户内容快照，即 `userPage.text` 与可选 `userPage.observations`；已有 `charPage` 的目标整条跳过，聊天卡也保持上一次成功交换时的快照。实现入口已由早期 `syncUserDiaryText` 扩展并更名为 `syncUserDiaryContent`。

## 2026-09-05 · 已交换日记广播保护与聊天卡快照

- `Boolean(entry.charPage)` 是唯一的“已交换”判定；`chatCardMessageId`、`isArchived` 与 `autoSync` 不参与广播资格判断。
- 普通保存始终先保存当前打开的日记，因此用户可以继续编辑双方正文、纸张和贴纸；跨日记本广播则只投递到没有 `charPage` 的记录。
- 广播入口与纯合并函数都进行同一保护检查，避免未来其他调用绕过入口覆盖已交换日记。
- 保存反馈分别统计成功同步、已交换跳过和失败角色，成功数不再把跳过或失败计入。
- 聊天卡只在首次成功交换或成功重写角色回复后创建/更新；普通保存与手动编辑角色页不改卡片，删除日记仍删除对应卡片。
- 每次打开日记时角色侧贴纸默认隐藏，用户可通过眼睛按钮在当前日记中临时显示；贴纸数据和编辑能力不变。

## 2026-08-31 · 日记本选择页结构与皮肤边界

- 选择页固定使用两列、内容高度行，并由日记本网格占据剩余空间独立纵向滚动；角色数量和角色分组不改变这一结构。
- 内置主题和自定义 CSS 可以调整网格的间距、内边距与背景，也可以完整设计单本日记的外观和内部排版，但不能改变列数、跨格或把日记本移出自己的 Grid 单元。
- 最终 Safety CSS 在主题与用户 CSS 之后锁定网格结构，并清除日记本本体的绝对定位、跨格、负外边距和位移缩放；伪元素装饰、阴影和卡片高度仍可由皮肤定义。

## 2026-09-05 · 可选结构化自我观察

- `DiaryPage.observations` 是向后兼容的可选字段；没有该字段的旧日记、旧聊天卡继续按原正文流程工作，不升级 IndexedDB 版本。
- 正文仍是日记主体。正文下方的“看看今天的自己”默认收起，可按需展开体能（睡眠、饮食、运动、身体）、情感、思维、意志和任意条“记录一件事情”。事件标题可选，正文保持一个自由文本框，四个问题只作书写提示。
- 保存前统一清理首尾空白：空字段不保存，空的体能对象与观察对象整体省略，标题和正文都没有意义的事件删除。历史日记只展示实际存在的模块；当天编辑页保留新增入口。
- 跨角色广播使用“正文 + 观察”的来源快照；已存在角色回复的日记整条跳过。纸张与贴纸仍属于各自日记本，不参与广播。
- 主动交换通过 `serializeUserDiaryForExchange()` 把现有模块转换成自然中文，不向模型发送原始 JSON。聊天卡可选保存 `userObservations`，界面与后续聊天上下文都只呈现实际存在的模块。
- 本阶段不做跨日趋势、历史统计、图表、自动标签、AI 分析、评分、周报或月报；未来若扩展，应继续以本地可选数据和用户主动分享为边界。

## 2026-09-06 · 书写页连续滚动修复

- 现象：正文在输入框内部单独滚动，与下方观察区割裂；展开事情记录后，底部新增按钮可能落入外层裁切区域。
- 根因：正文使用 `flex-1` 的固定可视输入框，观察框也有内部滚动；编辑舞台的多层 Flex 和主题双页 Grid 缺少可收缩的高度约束。
- 修复：正文、角色回复和所有观察笔记统一使用 `JournalTextarea`，随内容自动增高/缩短，关闭内部滚动及手动拖高。纸面的 `.sully-journal-page-content` 是唯一纵向滚动容器；补齐外层 `min-h-0` 与双页 Grid 的受限行高，让事件末尾的新增按钮留在可滚动内容中。纸面允许纵向触摸滑动，仅贴纸拖动保留 `touch-none`。
- 自动高度会在编辑、折叠区重新展开及宽度变化时重算，测量期间保留纸面滚动位置。没有改变保存、同步、聊天卡、AI 或数据结构。
- 回归：5 文件 38 项定向测试与 Vite 生产构建通过；新增代码测试覆盖增删长文、边框高度、滚动位置保留、折叠/重开和宽度变化，以及所有输入框与受限滚动层的接线。尺寸由 jsdom 模拟，按用户要求未执行浏览器/UI 测试，真实画面由用户验收。

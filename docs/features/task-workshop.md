## 最初开发需求

用户最初在 `UnitOS/` 中尝试以 SullyOS 为参考框架做独立产品，沉淀后决定只提取其任务管理意图，将其做成 SullyOS 内的新 App。新 App 不复用 UnitOS 的 UI、独立角色、API、向量库、MCP 设置或备份框架，也不和现有“时光契约”联动。

产品核心是一间持续存在的共享工作空间：任务盒和工具箱由用户维护；用户选择多位既有角色作为来访者，他们在 SullyOS 打开期间轮流查看整个工作空间，并针对一项当前任务留下有限、可编辑、可删除的建议。角色不是固定顾问，必须保持主聊天里的同一身份、关系、语言习惯和记忆连续性。

第一版明确边界：

- 自动来访只在 SullyOS 页面打开时运行，不做系统后台、Worker 或推送调度。
- 自动来访只写任务工坊本机记录，不自动写主聊天、角色长期记忆或记忆宫殿，不执行 MCP。
- 用户明确点击后，才能把某次建议或任务成果作为卡片带到指定角色的主聊天；需要工具时，也先回到主聊天，再由已有 MCP 工具循环执行。
- 来访内容不能无限累计。同一任务中同一角色只保留一份便签，再次来访覆盖自己的旧便签；用户可以编辑或删除。
- “角色将来可能主动抓取任务工坊内容形成提醒或建议”只作为后续方向记录，第一版不实现。

## 第一版实施计划

### 1. 产品结构

- 独立桌面 App `AppID.TaskWorkshop`，普通应用身份接入桌面长按换位，不进入底部四个固定软件。
- 首页采用“共享工作台”结构：上方显示来访轮转状态，中间为任务列表，工具箱作为同级分段入口，不复制 UnitOS 原界面。
- 任务详情包含说明、标签、状态、过程记录、步骤、关联工具和角色来访便签。

### 2. 数据模型

- `TaskWorkshopUnit`：任务盒，保存任务正文、状态、标签、记录、步骤、关联工具和有限来访便签。
- `TaskWorkshopTool`：工具箱条目，保存能力说明、可用状态、标签和备注；它描述“能用什么”，不直接执行外部工具。
- `TaskWorkshopSettings`：来访角色顺序、间隔、开关、轮转游标与上次来访时间。
- IndexedDB 使用独立 `task_workshop` store，并进入完整备份导出/导入。

### 3. 角色来访

- 常驻运行层由 PhoneShell 挂载；每分钟检查一次到期状态，页面从后台回到前台时再检查一次。
- 每个周期只选择一位来访角色，并按用户排列的角色列表轮换。
- 在未完成、未归档的任务中按“阻塞优先、活跃其次、最久未被该角色查看”选一项；没有可处理任务时不调用 API。
- 角色生成的内容限制为：一段观察、最多三条建议步骤和一个最小下一步。写入前再次确认任务仍存在，避免删除/编辑期间产生幽灵便签。

### 4. 上下文、记忆与 API

- 复用 SullyOS 主聊天 API 配置与 `buildChatRequestPayload()`；角色身份、主聊天历史、实时状态和记忆宫殿召回保持统一。
- 为非聊天 App 调用增加显式 `disableMcp` 入口。自动来访仍可读取主聊天上下文和既有记忆，但提示词中不出现工具清单，也不进入任何工具循环。
- 任务工坊不另建角色、聊天模型、向量 API、记忆 MCP 或独立设置。记忆宫殿若启用，沿用系统默认向量化配置完成召回。

### 5. 用户主动写回

- 用户可将来访便签作为 `score_card` 写入所选角色的主聊天，卡片包含任务、角色建议、建议步骤和下一步。
- 写回不自动追加长期记忆；卡片自身会像其他结构化消息一样进入后续聊天上下文，并由系统既有归档/记忆流程按统一规则处理。
- “带到聊天处理”会先写卡并切换到该角色聊天。若用户希望角色调用 MCP，继续在主聊天中明确要求即可。

## 初版实现

### 用户流程

- 桌面进入“任务工坊”后，可在“任务盒 / 工具箱 / 来访”三个分段间切换。
- 任务支持标题、说明、标签、收件箱/进行中/阻塞/完成/归档状态、过程笔记/进展/阻塞记录、可勾选步骤和关联工具。
- 工具支持能力说明、限制备注、标签、可用/受限/不可用状态，以及可选的“到日恢复可用 / 到日变为不可用”；到期只切换状态，不删除条目。
- 来访页选择多位角色并调整轮换顺序、间隔和开关。打开自动来访后，PhoneShell 常驻运行层在页面可见时检查到期状态。
- 任务详情可临时邀请任意角色立即查看；角色便签可编辑、删除，建议步骤可采纳为任务步骤。
- 用户可将完整任务快照或某位角色的便签带到指定角色主聊天；完成写入后直接切换到该角色聊天。

### 角色上下文与记忆

自动来访通过 `buildChatRequestPayload()` 读取最多 80 条未归档近窗和既有记忆宫殿召回，沿用主 API、角色资料、用户资料与实时上下文。`disableMcp: true` 使自动来访不注入 MCP 工具清单，也不被标记为工具轮次。任务工坊内容不会自动写回聊天或记忆。

### 隐私与写回

全部任务、工具和便签默认只存在本机。只有用户点击“带任务进聊天”或“带到聊天处理”才产生 `task_workshop_card`。卡片本身进入统一聊天时间线，但首版不直接修改 `char.memories`，也不主动调用记忆宫殿处理钩子。

### 数据、备份与恢复

IndexedDB 升级到 v75，使用 `task_workshop` store。`FullBackupData.taskWorkshopRecords`、普通完整导出/导入和 OSContext 分片备份映射均已接入。

### 入口与界面

`AppID.TaskWorkshop` 已注册普通桌面 App、懒加载、按压预加载、空闲预热、自理安全区和动森图标，因不属于 Dock 四项而自然参与既有长按换位。

## 迭代与 Debug 记录

### 2026-10-20 · 待公开版本撤回共享提醒控制台

- 10 月 12 日加的「提醒」分段、共享生活提醒控制台和关联生活提醒入口已从公开代码移除。任务盒、工具箱、角色来访、便签和归档仍以 2026-08-16 `ae620d33` 附近的行为为准。旧记录上的 `linkedReminderIds` 可以留在数据里，界面不再使用。

### 2026-08-11 · SullyOS 运行时无法移动 UnitOS 目录

- 现象：SullyOS 开发服务器运行时，Windows 提示 `UnitOS/` 正被其他程序使用；关闭 SullyOS 后可以移动。
- 根因：业务代码没有依赖该目录，但 Vite 默认会从根目录发现 HTML 入口，并由文件监听器观察项目树；嵌套原型的 `index.html` 与源码因此可能被开发进程打开。
- 修复：`vite.config.ts` 将 `optimizeDeps.entries` 固定为 SullyOS 根 `index.html`，并在 `server.watch.ignored` 中排除 `UnitOS/unityos`。任务工坊运行仍只依赖 SullyOS 自身代码与 IndexedDB。
- 回归：生产构建；开发服务器运行期间执行目录原子改名探针，完成后还原原目录名。
- 提交：`3ec5cff2`

### 2026-08-11 · 从 UnitOS 迁入 SullyOS 的产品决策

- 现象：UnitOS 已经复制了 SullyOS 的设置、API、向量、MCP 和备份框架，但任务功能本身仍处于原型状态。
- 根因：最初按独立产品搭建，后来产品方向改为 SullyOS 内的一个 App。
- 修复：只迁移任务盒、过程记录、步骤、工具说明和角色轮流来访意图；完全复用 SullyOS 的角色与基础设施。
- 回归：第一版实现完成后补充。
- 提交：`4dcc0a31`

### 2026-08-12 · 工具日期规则与现实边界

- `TaskWorkshopTool` 增加可选 `availableFrom` / `unavailableFrom` 本地日期。App 读取和前台调度时会选择“已经到达的最近一条规则”切换状态；同日冲突时不可用优先，条目始终保留。
- 来访提示词明确任务工坊不是线下见面或共同世界：角色是虚拟角色，只能留下建议、规划和情绪支持，不能用动作描写声称替用户理发、做饭、收拾、购买或完成其他现实事项。
- 第一版继续 `disableMcp: true`。未来接入 MCP 后，也只有用户明确授权的实际工具调用可以产生外部效果，普通来访文字本身不能。

### 2026-08-16 · 归档任务集中折叠

- 现象：任务盒原先只按更新时间统一排序，已归档任务会与收件箱、进行中、阻塞和已完成任务混在一起，占用主要浏览空间。
- 修复：保持各组原有的更新时间顺序，将所有 `archived` 任务稳定移到任务盒末尾；末尾默认只显示“已归档”标题和数量，用户点击后一次展开全部归档任务，再次点击可收起。
- 边界：归档只改变任务盒的展示分组，不迁移或删除记录；展开后仍从原入口进入任务详情，状态编辑、删除和备份行为不变。
- 回归：任务工坊、任务工坊存储、任务卡片格式及安全区共 4 个文件 8 项测试通过；Vite 生产构建通过。
- 提交：`ae620d33`（`feat: collapse archived workshop tasks`）。

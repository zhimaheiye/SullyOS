# 角色自习室 · 费曼课堂

## 档案信息

- 类型：现有“自习室”App 的独立子模块，不新增桌面图标。
- 当前状态：首版业务代码、私密存储、备份、测试和手机端入口检查已完成；仍需用户用真实 API 验证连续课堂。
- 首版日期：2026-08-10。
- 首版提交：`c6643602 feat: add character study room and feature archives`。

## 最初开发需求

- 原自习室只有角色教用户；新增通用的“角色自习室”，用户每次选择谁来当学生，不为不同角色复制多个房间。
- 预置提示词要自然解释角色为什么此刻愿意学习当前主题。
- 上半屏是可滚动的小黑板，右侧有可以按住拖动的进度条；黑板用 Markdown 持续记录角色笔记。
- 角色没有讲义，只根据用户逐句讲述做总结；每回合用户都可以选择是否允许角色提问。
- 提问要服务费曼学习，聚焦笔记里的易错点和解释缺口，不要随机装傻或反过来给用户讲课。
- 角色进入课堂时保留较轻的聊天语境：约 50—100 条即可，不读取向量记忆。
- 整个学习过程不会总结或写回角色长期记忆；核心目标是让用户通过讲述和回答问题加深理解。

## 初版实现摘要

- 在自习室书架页加入“这次换你来讲”的入口卡，不改变原 PDF 课程、角色助教、测验和练习册流程。
- 用独立 `CharacterStudyRoom`、`useCharacterStudy` 与 service 分离界面、会话状态和 API，避免继续扩大原有近两千行 `StudyApp` 的职责。
- 开课生成入座理由、角色开场白和初始黑板；每轮严格解析新增笔记、听课反应和可选问题。
- 自绘黑板滚动条支持点击定位和按住拖动；笔记增量追加并自动滚到最新内容。
- IndexedDB v73 `character_study_sessions` 私密保存课堂，支持退出续读、结束后回看和完整备份。

## 实现过程中的修正记录

### 2026-08-10 · 隐私边界收紧

- 初始设计只清空月度/日度记忆和向量注入，但 `ContextBuilder` 仍可能读到印象档案、自我领悟和房间门牌。
- 修正为在角色副本中同时清空这些记忆衍生字段，只保留角色人设、世界观与最近 50 条私聊语境。

### 2026-08-10 · 首轮笔记与异步交互

- 初始黑板的“等待讲解”占位若直接追加，会在第一轮后长期残留；现在首次追加前由本地函数确定性移除。
- 角色整理笔记期间若允许返回或结束，异步结果可能重新打开课堂或覆盖结束状态；现在等待期间锁定这两个入口。
- 课堂历史卡最初存在交互元素嵌套；已改为可键盘打开的卡片容器和独立删除按钮，避免点击与无障碍冲突。

### 2026-08-10 · 验证记录

### 2026-08-11 · Markdown 导出与数学公式

- 新需求：课堂黑板笔记可导出为 Markdown 文件，文件名使用开课时填写的“今天要讲什么”。
- 实现：课堂页标题栏新增“导出”，直接导出 session 的 `notesMarkdown`；复用全局 `shareOrDownloadFile()`，在 Capacitor、移动浏览器和桌面浏览器分别使用系统分享、Web Share 或下载兜底。
- 文件名：使用对话主题并清理 Windows 文件名中的非法字符，主题为空或只剩尾部句点时回退为 `课堂笔记.md`。
- 问题：角色会在笔记中生成 `$2^{32}$` 等 LaTeX，但角色黑板原先的轻量 Markdown renderer 只认识粗体、斜体和代码，因而原样显示美元符号。
- 修复：复用 `StudyApp` 已加载的 KaTeX 实例，支持 `$...$` 行内公式和 `$$...$$` 单行块公式；未加载或公式格式损坏时保留可读源码，不让整块笔记消失。
- 验证：`utils/characterStudy.test.ts` 4 项通过；Vite 生产构建成功，5221 modules transformed。按用户要求未进行前端页面测试。

### 2026-08-12 · 初学者心象与知识边界

- 每个新回合增加可选 `beginnerThinking`：它描述角色作为初学者如何抓住用户本轮关键词、连接课堂前文、形成暂时理解并暴露疑点，通过主聊天同款 `ThinkingChainBlock` 展示。
- 这不是模型幕后推理，也不代表标准答案。提示词要求只使用用户本轮/此前课堂讲述、黑板和角色人设，不得用模型先验知识补定义、例子或结论。
- 听课回应从一句寒暄提高为 2—4 句有内容的反馈；心象要求 3—6 个简短步骤，提问规则保持不变。
- 最近 50 条私聊只在开课时用于生成自然入座理由和语气；进入课堂后不再重复注入，后续只使用角色基础人设、黑板和最近 12 个课堂回合。

## 产品边界

角色自习室是现有“自习室”里的第二种学习方式：用户是讲解者，所选角色是学生。它服务于用户自己的费曼学习，不把课堂虚构成新的共同经历。

- 所有角色共用一个入口与课堂列表；每次开课再选择学生，不按角色复制 App。
- 角色没有讲义，只能把用户已经讲过的内容整理为 Markdown 黑板笔记。
- 每回合用户单独决定是否允许提问。允许时，角色只在概念边界、因果跳步、适用条件、反例或易混淆项确有疑点时问一个具体问题。
- 课堂与笔记默认完全私密，不提供聊天写回按钮，也不生成长期记忆。

## 上下文与记忆

`utils/characterStudyService.ts` 刻意不复用会调用向量召回的聊天请求链路。

1. 用角色档案的副本构建基础人设；副本会清空长期记忆、印象档案、自我领悟、房间门牌和 `memoryPalaceInjection`，并关闭 `memoryPalaceEnabled`。
2. 开课时从私聊中只取最近 50 条用户/角色消息，经 `normalizeMessageContent()` 规范化后作为轻量语境；正式讲课回合不再重复携带这批聊天。
3. 正式讲课只追加最近 12 个课堂回合，完整黑板另行传入。
4. 全流程不调用 `injectMemoryPalace()`、`processNewMessages()`、`updateCharacter()` 或 `DB.saveMessage()`。

因此，角色会保持身份和最近聊天语气，但不会读取向量化记忆，也不会把课堂内容写回聊天、月度记忆或记忆宫殿。

## 生成契约

开课返回严格 JSON：

```json
{"rationale":"角色为什么愿意学","opening":"角色的开场白","notesMarkdown":"# 主题\n\n> 等待讲解"}
```

每回合返回严格 JSON：

```json
{"notePatch":"本回合新增 Markdown","beginnerThinking":"3—6步初学者理解过程","response":"角色的听课反应","question":"问题或 null"}
```

`notePatch` 由本地代码增量追加，模型不能替换整块黑板。若本回合禁止提问，即使模型错误返回了问题，解析层也会强制丢弃。

## 数据与界面

- IndexedDB v73：`character_study_sessions`，保存主题、学生、入座理由、黑板、课堂回合与状态。
- `CharacterStudyRoom` 是独立子界面，现有 PDF 助教、测验和练习册逻辑不变。
- 黑板上半屏显示 Markdown；右侧自绘滚动条同时支持点击定位和按住拖动。
- 黑板使用自习室既有 KaTeX 渲染 `$...$` / `$$...$$` 数学公式；课堂标题栏可把原始 Markdown 按主题名导出。
- 课堂可以退出后继续，结束后只读保留；完整备份会导出/恢复这些私密课堂。

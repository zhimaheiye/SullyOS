# 聊天输入框 · 表情包快捷触发

## 目标

用户只有主动输入特殊符号和搜索文字时才看到表情包候选，避免低频使用的表情包长期干扰聊天输入。首版触发格式为 `[关键词`，例如 `[想哭`。

## 交互约定

- 只输入 `[` 时不展开；至少输入一个连续、无空白的字符后才显示。
- 候选浮在输入框正上方，最多展示 20 个名称包含关键词的表情包，可横向滚动。
- 搜索范围是当前角色有权看到的全部表情分类，不受普通表情面板当前分类影响。
- 点击候选后只删除当前光标前的 `[关键词` 片段，保留前后原文，并把表情包作为独立 `emoji` 消息立即发送。
- `Escape`、删除触发符、输入空白、移动光标离开有效片段或点击关闭按钮都会关闭候选。
- 直接点击加号或普通表情按钮时也会关闭快捷候选，原面板行为不变。

## 最近使用

`Emoji.lastUsedAt` 只用于同一搜索结果内的快捷候选排序。无论从普通面板还是快捷候选发送，都会更新 IndexedDB 中对应表情的时间戳；普通分类面板仍保持原有顺序，不因快捷排序改变。

## 数据与发送边界

- 不创建新的消息类型，继续调用 `onPanelAction('send-emoji', emoji)`。
- 不复制图片，不改变 `MessageItem` 的 `emoji` 渲染，也不引入 AI 请求。
- `lastUsedAt` 是可选字段，旧表情和旧备份无需迁移。

## 关键入口

- 触发解析与候选排序：`utils/emojiTrigger.ts`
- 输入框与浮层：`components/chat/ChatInputArea.tsx`
- 全分类可见范围、发送和最近使用更新：`apps/Chat.tsx`
- IndexedDB 时间戳：`utils/db.ts`

## Debug 前置检查

1. 确认测试输入包含半角 `[`，且后面至少有一个非空白字符。
2. 若搜不到跨分类表情，检查 `triggerEmojis` 是否传入当前角色可见的完整表情集合。
3. 若点击后文字误删，检查 `selectionStart`、`triggerStart` 和光标是否仍指向同一片段。
4. 若候选顺序不更新，检查 `DB.touchEmoji()` 与本地 `setEmojis()` 是否都执行。
